# M8：e1000 / e1000e 最小网络

原始自包含驱动，使用 Intel legacy RX/TX descriptors：
[8254x 手册](https://www.intel.com/content/dam/doc/manual/pci-pci-x-family-gbe-controllers-software-dev-manual.pdf)、
[82574 数据手册](https://www.intel.com/content/dam/doc/datasheet/82574l-gbe-controller-datasheet.pdf)。
仅匹配 Intel PCI ID 8086:100e（82540EM）、100f（82545EM）、10d3（82574L）。
不宣称支持所有名为 e1000/e1000e 的硬件。需要有效的 RAR0 MAC 和受支持
的 32-bit memory BAR0；无设备/其他型号明确 skip，不拖垮回归。

`enet0` 静态配置为 10.0.2.15/24，网关/唯一邻居 10.0.2.2，与 QEMU user
network 对齐。产品首选已注册的 `vnet0`，其次 `enet0`；两个都在时
virtio-net > e1000，即使首选链路 down 也如实显示 down，不是自动故障
切换服务。横幅会显示 `nic=enet0/up`、`vnet0/up` 或 down/unavailable。

单 RX/TX 队列，各 16 项 legacy descriptor，单 TX in-flight，RX 2048B
缓冲，CPU copy、同步轮询。关闭 checksum/GSO offload 与中断，不增加
IRQ 路由；异常 completion/TX 超时后复位并关闭 bus mastering，确认
复位和 DMA off 后才回收页，否则隔离保留。坏帧/不支持帧丢弃；不可能
的 DMA 地址/长度视为设备错误。TX 有 1 秒/200 万次上限（TSC 校准前
仅迭代上限），设备复位有 10 万次上限。

ARP/IPv4/ICMP 复用 M4 编解码及校验，每次探测独立邻居和 echo 状态。
接收仍先经 XDP/nft；校验 MAC、IPv4/ICMP checksum、id/seq 和完整 payload。
保留既有 33B 测试字符串 `CapMix virtio-net off-lo payload!`；名称不表示
回包来自 virtio，e1000 的包确实走自己的 DMA 环及 QEMU 后端。
debug 执行 9 次探测（至少 18 TX/RX），跨过 16 项环，验证 descriptor reuse。
没设备则 skip；有设备但 link/ARP/echo 失败则报告 FAIL，不能伪造 RX。

## 验收

```bash
make kernel
make test
make iso LIMINE_CONFIG=boot/limine-selftest.conf

timeout 30 qemu-system-x86_64 -enable-kvm -m 512 -cpu host -smp 4 \
  -cdrom capmix.iso \
  -netdev user,id=n0 -device e1000,netdev=n0 \
  -serial stdio -display none -no-reboot
# 替换为 -device e1000e 或 e1000-82545em 验证对应型号。
# 可加已有专用 virtio/AHCI COW 盘，勿重新截断已有盘。
# 无网卡：用 -nic none，应见 e1000 skipped 和完整 PASS。

make iso                           # 默认产品 shell，不跑网络探测
# 复用以上网卡参数；可用 -display gtk 输入 help/run/poweroff。
```

双网卡分别使用两个 user netdev，避免共享同一 backend：

```bash
-netdev user,id=n0 -device virtio-net-pci,netdev=n0,mac=52:54:00:12:34:01 \
-netdev user,id=n1 -device e1000,netdev=n1,mac=52:54:00:12:34:02
```

两个隔离的 QEMU user backend 分别有自己的 10.0.2.2，debug 分别校验
virtio 和 e1000；产品横幅应选 vnet0。不要把两块同 IP 网卡放入同一个
真实二层网络来充当路由/多网卡产品化实现。

关键日志：`e1000 PCI`、`e1000 ready: link=up`、`e1000 ip`、
`e1000 ARP rx`、`e1000 tx/rx payload verified`、
`m8 e1000 ring wrap verified`、`m8 e1000 selftest: PASS`、
`selftest result: PASS (0 failures)`。无设备：`e1000 skipped`、
`m8 e1000 skipped`。产品：`net primary: enet0`、`nic=enet0/up`、`shell ready`。

## 首版边界 / VMware

沿用 M6 UEFI 与 M7 SATA 设置；可选择 E1000/E1000E，但必须核对实际
PCI ID 在上述名单中。VMware NAT/桥接网段未必是 10.0.2.0/24，因此
link up 不代表 QEMU 固定地址探测能通过。没有 DHCP、TCP、通用路由、
后台 RX 服务、用户 socket 到这块 NIC、MSI-X 多队列或 vmxnet3 驱动。
产品启动只初始化 NIC/显示链路，不依赖 QEMU peer 探测通过。
QEMU 验证不等于 VMware NIC 或真实硬件 PASS。
